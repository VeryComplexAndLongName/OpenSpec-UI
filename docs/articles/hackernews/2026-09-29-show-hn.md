## First comment

    Hi HN. OpenSpec gives a coding agent something to build from: a proposal, a
    design, a task list. There are a handful of good viewers for those files,
    but I could not find one that also starts the agent, shows what it is doing,
    and lets me stop it, so I built that: a local web app and a VS Code
    extension over the same core.

    What it does: it runs an agent CLI (Claude, Copilot, Codex, Gemini or a
    local model) through propose, review, apply, verify, archive and git for
    a change, with the agent chosen per stage. Each run says what it last did
    and how long ago. It never calls a run "stuck", because a long turn and a
    hang look the same from outside. A stop asks for a reason and is signed, and
    the run stops where its work is sound. There are ceilings for time and
    spending, and an audit log.

    To try it: `code --install-extension openspec-ui.openspec-ui-vscode`, or
    clone the repo and run the three commands in the README. It runs on your
    machine, against your own agent CLIs; no account, and it never handles an
    API key.

    What I would like to know: whether the run card shows what you would want to
    see, and what is missing.

    What does not work, so nobody is surprised: Claude CLI and Copilot CLI have
    been run against the real binaries; Codex and Gemini never have, only
    against mocked peers. Over ACP, the Claude adapter never asks for
    permission, and `copilot --acp` completed writes here without asking. A
    spending ceiling counts only what an agent reports, and six of the ten
    agents report nothing, so only the time ceiling can stop those.

    The repository and the packages are still called OpenSpec-UI; the product is
    OpenSpec Workbench. I wrote about how it came out this way at
    https://openspec-ui.dev/articles/a-viewer-is-not-a-cockpit/
