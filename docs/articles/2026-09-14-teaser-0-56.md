Running four agents at once is easy. Knowing what each of them is doing is
not, and stopping the right one is harder still.

Twelve releases of OpenSpec Workbench, 0.44 to 0.56, went at exactly that,
in three steps.

**Run more than one.** A change runs from a terminal, with exit codes a CI
job can tell apart. Several run side by side, each in its own git
worktree, each holding its own lease. Which may share a moment is decided
from the capabilities their spec deltas name and the files their branches
touched. `openspec-ui-cli ready` says what can start now.

**See what each one is doing.** Every run writes a status record: the stage, the
tool it is running, the last line it wrote, and how long ago. It never says
"stuck". A long turn and a hang look the same, and that call stays a
person's. The Pipeline draws every change and every working directory in
the standalone app and in VS Code. One word says where each change stands,
on every surface: Running, Waiting for you, Failed at verify, Merged in
#N.

![The Pipeline, with a failed change opened to its tasks](../images/standalone/pipeline.png)

**Stop the right one.** Each run is signed with its person's machine key. A
card's Stop asks for a reason, and the run stops where its work is sound:
at a checkpoint, on a permission, or between tasks, never mid-edit. A run
in another working directory can be asked too, but only by the person it
belongs to. The request is a signed file the run reads within seconds, and
it is refused after sixty. From a terminal: `openspec-ui-cli stop`.
