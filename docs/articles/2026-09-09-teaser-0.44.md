I shipped a feature that showed exactly the right thing and saved none of it.

Three named configurations for an agent harness, each setting spending and
time ceilings drawn from measured runs. You pick one. The form fills. The
diagnostic panel recomputes and agrees. A message says, truthfully,
"nothing is saved until you save."

Then you save, and every ceiling is gone.

The settings view sent two of the eight accepted configuration keys, and
the writer replaces the file. So everything a template exists to set was
deleted on the way out — the timeouts, the budgets, the attempt counts,
and the list of paths the agent is allowed to stage.

![The per-change settings section, with the three named configurations](../images/standalone/harness-change-override.png)

No test caught it. Every test looked at the half that was correct.

That turned out to be the shape of five separate defects across one
release cycle, every one found the same way: by a person opening the
thing that came out and reading it.

A template promised "no checkpoints between stages" and its configuration
never said so, so it paused at every one. A chain's verify stage was built
to send unfinished work back — and the gate in front of it returned
"failed" before that code could run, making the one case it was written
for the one case it could not reach. A run cut by a time limit showed the
reason on screen and wrote nothing to the audit log. And a source file
held a raw NUL byte: it compiled fine, and made `grep` treat the file as
binary and skip it silently. A file no search reaches is a file nobody
reviews.

Five different bugs. One shape: the visible half was right and the
acted-upon half was not.

A test that looks at the visible half passes every single time. That is
not a gap in tests; it is what tests are.

![The Run dialog: the resolved path, the setting it read, each stage's agent, the ceilings, and the recommended configuration](../images/standalone/run-dialog.png)

So the entry that starts a run does the opposite now. Before it starts
anything it says what it read: which path will run and which setting
decided that, which agent runs each stage, which stages have no agent at
all, whether every ceiling can act — said either way, because silence
makes "examined and fine" look like "not examined" — and which
configuration it recommends, with the observations behind it and a button
to apply it.

The configurations are named for what you are actually choosing between,
with the figures in the title: Minimum cost, up to $3. Balanced, up to $5.
Fastest, up to $25. And "Fastest" says what makes it fast, because nothing
here makes an agent work faster — the run stops waiting for you, and its
ceilings are wide enough that a stage is not cut and started over.

That last part is worth the sentence: a stage cut at a ceiling is retried
from the start, so a tight ceiling makes a run take longer.

The lesson I keep relearning: a ceiling that cannot act is worse than no
ceiling, because it reads as protection.
