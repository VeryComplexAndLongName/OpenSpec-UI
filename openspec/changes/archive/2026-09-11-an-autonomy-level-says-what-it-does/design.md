# Design

## Decision: the label states the behaviour

Each option reads as what choosing it does — stages one at a time, a
chain confirming between stages, a chain without confirmations. A
person choosing between three words needs the difference, and
"(not yet implemented)" was the only difference on offer.

## Decision: the options are computed per scope, not shared

One list served both sections, which is how the global select came to
offer a value only a change may set. The options are derived from the
scope the select belongs to, so the refusal that already lives in
`writeGlobalHarnessConfig` has nothing left to refuse.

Leaving it offered and disabled was rejected: unlike a stage whose agent
takes no effort, this is not a fact about the reader's configuration
that they might want explained. It is a value that does not exist at
this level at all.

## Decision: the guide stops apologising

`HARNESS.md`'s caption records that the screenshot shows stale copy.
Once the copy is gone the caption is wrong, and the screenshot is
regenerated by the browser suite that produces it.

## Non-Goals

Changing what a level does, adding a level, or touching the refusal in
`writeGlobalHarnessConfig` — that rule is correct and stays.

## Risks / Trade-offs

A per-change override that already sets `autonomous` keeps working; the
per-change select still offers it. Nothing stored changes meaning.
