Carries out the frame of ADR 0032: the component families, the icons and the
palette. The screens are `the-web-ui-screens-wear-metro`, which is blocked by
this change. The figures in section 1 were measured before the change was
written, by running `build-metro.mjs` with each family added.

## 1. The derived copy carries four more families

- [ ] 1.1 `KEPT_COMPONENTS` in `packages/webui/scripts/build-metro.mjs` becomes
  `["button", "input", "select", "textarea", "table", "panel", "card", "badge",
  "timeline"]`. Do not add `accordion`: no screen uses one, and a native
  `<details>` covers the only place that might.
- [ ] 1.2 `packages/webui/src/metro-css.generated.ts` is regenerated by
  `npm run build:metro -w @openspec-ui/webui`. Record the new byte count and
  rule count the script prints.
- [ ] 1.3 `packages/webui/scripts/build-metro.test.mjs` asserts the derived
  copy's byte count against a stated ceiling and names the figure in its
  failure message, so a later family shows up as a changed number in review.
- [ ] 1.4 `vscodeThemeCss` in `packages/webui/src/shell-ui.ts` sets all 18 new
  Metro variables from `--vscode-*` tokens: `--panel-background`,
  `--panel-color`, `--panel-border-color`, `--panel-border-radius`,
  `--panel-header-background`, `--panel-header-color`, `--card-background`,
  `--card-color`, `--card-border-radius`, `--card-header-background`,
  `--card-header-color`, `--card-footer-background`, `--card-footer-color`,
  `--card-button-border-color`, `--badge-background`, `--badge-color`,
  `--badge-border-radius`, `--timeline-marker-color`. Write no literal colour.
- [ ] 1.5 `packages/webui/src/vscode-metro-mapping.test.ts` passes against the
  regenerated copy, which is what proves 1.4 complete. Record its test count.

## 2. Icons

- [ ] 2.1 The Metro icon font of the pinned 5.1.20 is vendored under
  `packages/webui/vendor/metro-icons/` with its licence and a README naming the
  source, the version and the file's byte count, the way `vendor/metro/`
  records `metro.css`.
- [ ] 2.2 `packages/webui/scripts/build-metro-icons.mjs` writes
  `packages/webui/src/metro-icons.generated.ts`: one `@font-face` whose `src`
  is a `data:` URI of a subset holding only the named glyphs, plus one class
  per glyph. It does not read `vendor/metro/metro.css`.
- [ ] 2.3 `packages/webui/src/icons.ts` exports `ICONS`, the map from a meaning
  this product names — `change`, `spec`, `archive`, `task`, `run`, `stop`,
  `refresh`, `review`, `open`, `settings`, `agent`, `timeline`, `warning`,
  `ok` — to its glyph name, and `iconFor(meaning)`. A screen names a meaning;
  it never writes a `mif-` class.
- [ ] 2.4 `packages/webui/src/icons.test.ts` fails when `ICONS` names a glyph
  the generated module does not carry, and when the generated module carries a
  glyph nothing names.
- [ ] 2.5 `packages/webui/scripts/build-metro-icons.test.mjs` asserts the
  generated module matches a fresh run, the way `build-metro.test.mjs` does,
  and asserts its `@font-face` carries a `data:` URI rather than a path.
- [ ] 2.6 `packages/webui/src/components/Icon.tsx` renders
  `<span className={iconFor(meaning)} aria-hidden="true" />` and nothing else.
  Its test renders one inside a button and asserts the button's accessible
  name is the label alone.

## 3. The palette declares a hue with its ink

- [ ] 3.1 `shellThemeCss` in `packages/webui/src/shell-ui.ts` declares each
  filled hue together with the ink used on it, in both themes: white on
  cobalt, indigo and crimson; dark ink on green, orange, teal, emerald, amber
  and steel. Measured with white: cobalt 8.3:1, indigo 9.9:1, crimson 5.0:1;
  green 2.8:1, orange 2.0:1, teal 2.1:1, emerald 2.1:1, amber 1.5:1, steel
  3.2:1.
- [ ] 3.2 `packages/webui/src/shell-ui.test.ts` computes the contrast of every
  declared hue-and-ink pair and fails below 4.5:1. It reads the pairs out of
  the stylesheet rather than from a list written beside it, so a pair added
  later is checked too.
