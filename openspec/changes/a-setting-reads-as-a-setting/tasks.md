Three faults were reported and all three are real. The fourth, unnamed,
is that the look was never chosen: cream, one teal accent, and every
block on the same rounded card with the same shadow.

## 1. The decision

- [x] 1.1 `docs/adr/0023-standalone-shell-visual-direction.md`: the
  standalone shell commits to an editor-native look, and the reason is
  that this product has two kinds of screen — dense forms and long
  prose — which the more characteristic directions each fought.
- [x] 1.2 Record the three rejected directions with what each cost, not
  only that they were rejected. They were drawn on the real Harness
  Settings screen and compared; a later reader deserves the comparison
  rather than the verdict.
- [x] 1.3 Record that the extension is untouched and why: it maps the
  same tokens onto the editor's theme, and a tool that repainted its own
  panel inside somebody's editor would override their choice.
- [x] 1.4 `docs/adr/README.md` gains the row.

## 2. Tokens before anything visible

- [x] 2.1 Every colour literal in `shellThemeCss` moves into `:root`
  under a name for what it is for — `--diff-added-bg`, not
  `--pale-green`. 21 unique values, 29 occurrences, measured
  2026-09-11.
- [x] 2.2 `vscodeThemeCss` defines every token the shell declares. A
  token present in one layer and absent from the other renders the
  extension's panel with a missing value.
- [x] 2.3 A test walks the shell layer's `:root`, collects the names,
  and asserts the extension layer defines each one. Nothing checks this
  today, which is why it is worth a test rather than a careful commit.
- [x] 2.4 A test asserts no rule outside `:root` contains a colour
  literal. It is the only thing that keeps 2.1 true a month from now.

## 3. The three faults

- [x] 3.1 The gap within a field becomes smaller than the gap between
  fields. This is the whole of the name/value fix: at 6px inside and
  12px between, a label belongs to the control above it.
- [x] 3.2 A field's name gains weight and tracking, so it is told from
  prose by more than being a paler grey. Not colour alone — it is the
  distinction a reader who cannot see it loses, and the one that fails
  contrast first.
- [x] 3.3 Controls take a width from the kind of value they hold. This
  is what brings the dropdown arrow back beside its word.

  Built differently from how it was written, and the screenshot is why.
  Fixed widths clipped the autonomy level to "assisted — one stage at a
  time, a cl" — a width guessed per control is exactly how that
  happens, and clipped text is a bug rather than a tight fit. A select
  is sized by its own widest option, which a browser already does well,
  with `--w-name` as a floor so a column of short ones stays tidy. Only
  inputs, which have no content to measure, take a named width; three
  tokens, not four. `--w-word` was declared, never referenced, and
  removed — a token nothing reads is what this change is about.
- [x] 3.4 A control that saves a section is separated from it by more
  than the fields are separated from each other.
- [x] 3.5 Where a row is a name and a value and nothing else, the name
  moves into its own column.

## 4. The look

- [x] 4.1 The palette: low contrast between surfaces, a neutral with a
  slight cool bias rather than a mid grey, one accent, and semantic
  colours kept separate from it.
- [x] 4.2 Radius small enough to soften a corner rather than announce a
  card. One shadow, spent only on what genuinely overlays.
- [x] 4.3 Border and fill separate; today the headline, the tab strip, a
  panel and a list row all carry the same border, radius and shadow, so
  none of them is emphasised.
- [x] 4.4 A type scale that stays out of the way, and a measure that
  keeps running prose near 65 characters — the proposal and timeline
  screens are prose and currently run the full width.

## 5. Contrast

- [x] 5.1 Every foreground/background pair meets WCAG AA. The muted text
  token is set from the contrast requirement, not from taste — a quieter
  palette fails there first.
- [x] 5.2 The browser suite's axe run is the gate and must stay green
  with no new serious or critical violation.
- [x] 5.3 Focus is visible on every control against the new surfaces.
  Check it rather than assume it: a quieter palette is exactly where a
  focus ring disappears.
